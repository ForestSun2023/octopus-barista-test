# 章鱼咖啡师测试 · Octopus Barista Test

[中文](README.md) · [English](README.en.md)

一个单提示词测试，用来观察 AI 编码 Agent 的**空间推理、多约束执行和代码生成**能力。灵感来自鹈鹕测试（Pelican Test：让模型画一只骑自行车的鹈鹕）。

> 同一款模型、同一份提示词，换不同的 Agent 工具，看谁真的把八条触手的活都干完了。

## 它比鹈鹕测试难在哪

鹈鹕测试主要看能不能把「鸟 + 自行车」两个物体摆对。章鱼咖啡师测试把压力集中在四点上：

| 考察点 | 具体表现 |
| --- | --- |
| 视觉结构构建 | 能否同时表示八条触手和多个独立物体 |
| 空间推理 | 接触、支撑、方向、遮挡关系是否说得通 |
| 多约束执行 | 能否遵循全部要求，而不是只完成最显眼的部分 |
| 程序生成 | 能否生成合法、可渲染的自包含 SVG 代码 |

画八条触手并不难，难的是**让每条触手完成不同的任务，同时保证整幅图在空间关系上说得通**。

## 测试指令

完整提示词见 [prompt.md](prompt.md)（当前 v2）。直接整段复制粘贴给 Agent 即可，不需要任何额外工具说明。

本仓库收录的 2026-10-13 轮次用的是 [prompts/v1.md](prompts/v1.md)，v2 只多了一条禁止用标注代替绘图的约束。

## 评分标准

**清单 v2：11 项，每项 1 分，满分 11 分。** 只有「代码质量」能自动判定，其余 10 项靠人工，且必须对着**渲染出来的图**找证据，不接受模型的文字说明。

盲评时把 [rubric/v2.md](rubric/v2.md) 交给评审者——那份文件里没有结果、没有 Agent 名称，不会泄露作品来源。

| # | 检查项 | 判定 | 通过标准 |
| --- | --- | --- | --- |
| 1 | 代码质量 | 🤖 自动 | SVG 合法、有 viewBox、自包含，无位图 / base64 / 外部资源 |
| 2 | 肢体数量 | 👁 人工 | 八条触手，从身体出发逐个编号，全程不出现「这里算一条还是两条」的犹豫 |
| 3a | 手柄抓握 | 👁 人工 | 触手末端落在手柄图形的边界上或内侧，容差见下 |
| 3b | 奶壶抓握 | 👁 人工 | 奶壶与触手有明确接触点，不是悬浮；容差同下 |
| 4 | 液体流向 | 👁 人工 | 奶流是一条连续路径，终点落在杯口内；中段断开或落到杯外都算不过 |
| 5 | 按钮交互 | 👁 人工 | 触手末端压在按钮图形上，而不是停在按钮旁边；容差见下 |
| 6 | 指向关系 | 👁 人工 | 轴线延长线穿过钟面，且末端到钟面最近点不超过容差；**不得用虚线、箭头或标注补齐这段距离** |
| 7 | 杯子与秤 | 👁 人工 | 杯底与秤台面贴合，中间看不到台面；容差见下 |
| 8 | 场景支撑 | 👁 人工 | 咖啡机、秤的底边与台面线重合 |
| 9 | 肢体连接 | 👁 人工 | 四条剩余触手的起点在身体上，不是从画面外伸进来 |
| 10 | 空间关系 | 👁 人工 | ① 遮挡前后一致；② 任意两条触手的轮廓重合段不超过较短那条可见长度的 **1/3**；③ 身体附近不得堆叠到无法逐条描出边界 |

第 1 项由 CI 每次 push 强制。投稿前先本地跑一遍（见 [CONTRIBUTING.md](CONTRIBUTING.md)）：

```bash
node scripts/check-svg.mjs
```

### 距离阈值

单位是**画布短边的百分比**，不是绝对像素——本轮画布从 1000×750 到 1600×1100 不等，写死像素对不同尺寸的作品不公平。

| 类型 | 容差 | 1200×800 | 1200×900 | 1600×1100 |
| --- | --- | --- | --- | --- |
| 接触：3a 手柄 / 3b 奶壶 / 5 按钮 / 7 杯与秤 | 短边 **1%** | 8 px | 9 px | 11 px |
| 指向：6 钟 | 短边 **5%** | 40 px | 45 px | 55 px |

接触类只留 1% 是为了容纳线宽和抗锯齿——「碰到」就是碰到，10px 的间隙不算碰到。指向类比接触松，因为钟挂在墙上、触手要跨过整个画面，方向对不对比贴不贴住更能反映空间推理。

用上一轮实测的争议值校准（原始测量见 [results/BLIND.md](results/BLIND.md)）：

| 实测 | 画布 | 末端到钟面 | 阈值 | 判定 |
| --- | --- | --- | --- | --- |
| ZCode | 1600×1100 | 45 px（射线偏差 1.8 px） | 55 px | 通过 |
| WorkBuddy | 1200×800 | 40 px，靠一条紫色虚线补齐 | 40 px | **不通过**——距离勉强够，违反第 6 项的禁止性规定 |
| Claude | 1200×900 | 80 px | 45 px | 不通过 |

### 评分表版本

| 版本 | 检查项 | 口径 |
| --- | --- | --- |
| [v1](rubric/v1.md) | 10 项 | 已发布分数来自 4 类加权（5 + 2 + 2 + 1），**不是**清单直接相加；清单还漏了奶壶抓握和触手交叠 |
| **v2（当前）** | 11 项 | 每项 1 分，满分 11；判据写死距离阈值 |

**判分原则**：不因为画得漂亮就给高分。画面精美但只有六条触手、牛奶流在杯子外面，照样扣分。

## 自己跑一遍

1. 新开一个 Agent 会话，把 [prompt.md](prompt.md) 里的提示词整段贴进去。
2. 把返回的 SVG 存成文件并渲染，逐项对照上面的评分标准检查——**先看结构，再看美观**。
3. 建议每个 Agent 独立运行 3 次，比较平均分与最低分，而不是只看一次结果。

## 说明

- 本仓库只收录 5 个 Agent 工具的结果。
- 每次 push 都会跑 `node scripts/check-svg.mjs`，任何不合法或含位图的 SVG 会让 CI 失败。
- 一次结果不能代表某个 Agent 工具或模型的整体水平，也不能据此判断 API 是否「降智」。模型输出本身有随机性，提示词、推理档位和运行环境都会影响结果。
- `scripts/<agent>/` 里的脚本是各 Agent 在生成过程中留下的，风格、质量差异很大，不代表测试要求，也不参与评分；`scripts/check-svg.mjs` 例外，它是评分表第 1 项的检查器。
