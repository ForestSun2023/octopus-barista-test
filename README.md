# 章鱼咖啡师测试 · Octopus Barista Test

一个单提示词测试，用来观察 AI 编码 Agent 的**空间推理、多约束执行和代码生成**能力。灵感来自鹈鹕测试（Pelican Test：让模型画一只骑自行车的鹈鹕）。

> 同一款模型、同一份提示词，换不同的 Agent 工具，看谁真的把八条触手的活都干完了。

## 它比鹈鹕测试难在哪

鹈鹕测试主要看能不能把「鸟 + 自行车」两个物体摆对。章鱼咖啡师测试把压力集中在四点上：

| 考察点 | 具体表现 |
| --- | --- |
| 视觉结构构建 | 能否同时表示八条触手和多个独立物体 |
| 空间推理 | 接触、支撑、方向、遮挡关系是否说得通 |
| 多约束执行 | 能否遵循全部要求，而不是只完成最显眼的部分 |
| 程序生成 | 能否生成合法、可渲染的自包含 SVG 代码 |

画八条触手并不难，难的是**让每条触手完成不同的任务，同时保证整幅图在空间关系上说得通**。

## 测试指令

完整提示词见 [prompt.md](prompt.md)。直接整段复制粘贴给 Agent 即可，不需要任何额外工具说明。

## 评分标准（20 项，每项 0.5 分，满分 10 分）

20 项**等权，不加权**。加权的话，权重怎么定每个人都有不同看法，最后变成吵权重而不是吵作品；等权才能把争议收敛到「到底是哪一项判错了」。

| # | 检查项 | 通过标准 |
| --- | --- | --- |
| 1 | 触手数量 | 正好八条 |
| 2 | 触手区分度 | 八条彼此可区分，无合并或重复肢体 |
| 3 | 手柄抓握 | 一条触手与手柄接触 |
| 4 | 手柄位置 | 手柄位于咖啡机出粉口下方，位置合理 |
| 5 | 奶壶抓握 | 奶壶被触手握住，不是悬浮在空中 |
| 6 | 奶壶姿态 | 奶壶的倾斜角度与倒奶动作一致 |
| 7 | 奶流连续 | 奶流中途不断开 |
| 8 | 奶流终点 | 奶流终点落在杯口内，没有流到杯外 |
| 9 | 按钮存在 | 咖啡机上有可辨识的按钮 |
| 10 | 按钮接触 | 一条触手确实接触按钮 |
| 11 | 指向动作 | 有一条触手朝挂钟方向伸出 |
| 12 | 指向精度 | 该触手的延长线指向钟面，不用虚线或箭头代替 |
| 13 | 杯与秤存在 | 咖啡杯和电子秤都存在且可辨识 |
| 14 | 杯放在秤上 | 杯子直接放在秤上，接触面贴合 |
| 15 | 场景支撑 | 咖啡机和电子秤都落在台面上 |
| 16 | 剩余肢体 | 其余四条触手清晰可见 |
| 17 | 肢体连接 | 所有触手都与身体相连，不是从画面外伸进来 |
| 18 | 遮挡关系 | 前后遮挡合理，物体没有明显穿插 |
| 19 | 触手交叠 | 触手之间不出现大面积交叠 |
| 20 | 代码质量 | SVG 合法、自包含，能正常渲染 |

**判分原则**：不因为画得漂亮就给高分。画面精美但只有六条触手、牛奶流在杯子外面，照样扣分。最好把生成的 SVG 实际渲染出来再检查结构，而不是只看模型给出的文字解释。

## 本轮结果

同一款模型 **DeepSeek-V4.1-Flash**，通过 5 个不同的 Agent 工具，使用同一份提示词，各生成一次。

| 排名 | Agent 工具 | 作品 | 得分 | 扣分项 |
| --- | --- | --- | --- | --- |
| 1 | ChatGPT | [chatgpt.svg](results/chatgpt.svg) | **10.0** | 无 |
| 2（并列） | ZCode | [zcode.svg](results/zcode.svg) | **9.5** | 19 触手交叠 |
| 2（并列） | WorkBuddy | [workbuddy.svg](results/workbuddy.svg) | **9.5** | 12 指向精度 |
| 2（并列） | DeepSeek Harness | [deepseek-harness.svg](results/deepseek-harness.svg) | **9.5** | 19 触手交叠 |
| 2（并列） | Claude | [claude.svg](results/claude.svg) | **9.5** | 5 奶壶抓握 |

每项等权，所以原评审用来拉开差距的依据（奶壶悬浮、触手交叠、细节密度）各自最多值 0.5 分，四份落在同一档。并列是这套标准的正常结果，不是漏判——不服气就直接指出哪一项判错了。详见 [results/SCORES.md](results/SCORES.md)。

## 仓库结构

```

CONTRIBUTING.md          投稿要求

results/*.svg            各 Agent 的最终作品（也是唯一被评分的产物）

scripts/render.mjs       SVG 渲染成 PNG，做预览图用
scripts/<agent>/         各 Agent 生成作品时留下的脚本，仅供参考
index.html               作品画廊
```

## 自己跑一遍

1. 新开一个 Agent 会话，把 [prompt.md](prompt.md) 里的提示词整段贴进去。
2. 把返回的 SVG 存成文件并渲染，逐项对照上面的评分标准检查——**先看结构，再看美观**。
3. 建议每个 Agent 独立运行 3 次，比较平均分与最低分，而不是只看一次结果。

## 说明

- 本仓库只收录 5 个 Agent 工具的结果。
- 一次结果不能代表某个 Agent 工具或模型的整体水平，也不能据此判断 API 是否「降智」。模型输出本身有随机性，提示词、推理档位和运行环境都会影响结果。
- `scripts/` 里的脚本是各 Agent 在生成过程中留下的，风格、质量差异很大，不代表测试要求，也不参与评分。
